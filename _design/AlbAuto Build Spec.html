01Summary

AlbAuto is a cross-platform mobile marketplace optimised for the Balkan region (North Macedonia, Albania, Kosovo) with a parallel Cars-for-Import flow covering Europe, Asia and Americas. The buyer surface is a tab-bar app with Home, Saved, Sell, Chats and Menu. The seller surface adds a multi-step posting flow with free and Top-Ad placement. The dealer surface adds a social-auto-import system (Instagram + Facebook), AI-assisted listing creation, and an analytics dashboard.

This document is the engineering brief: it lists every screen, component, data model, API endpoint, background job and integration the implementation requires. Where the design implies a system (rate limits, idempotency, offline behaviour, etc.) the requirement is called out explicitly.

Primary jobs-to-be-done

  • Find a car within my country / city / budget
  • Import a car from abroad with cost transparency
  • Talk to the seller safely without giving up my phone
  • Sell my car in under 5 minutes
  • Dealer: post inventory once, on Instagram, and have it live everywhere

Non-goals (v1)

  • End-to-end checkout / escrow payments
  • Auctions / bidding format
  • Parts and accessories
  • Insurance issuance (calculator only)
  • Cross-border car shipping logistics

08Auth & permissions

Three actor types in the mobile app, plus an admin web console.

RoleCanCannot
BUYERbrowse, favourite, chat with seller, save searches, request appointment, request financepublish listings beyond personal allowance (3 active)
SELLER (individual)everything in BUYER + up to 3 active listings, sell flow, mark soldconnect social accounts
DEALEReverything in SELLER + unlimited listings, social auto-import, analytics dashboard, multiple social accounts—
ADMINweb console only — moderation, verification, refunds, banimpersonate without audit log

Verification

Submit national ID (front + back) + selfie. Run liveness check + OCR. Async review by admin if confidence < 0.8. Verified users get the gold tick badge; required for Top-Ad placement and dealer mode.

Sessions

Rolling 30-day cookie; absolute 90-day limit. Refresh on every authenticated request. Force re-auth on phone-number change. Provide "log out everywhere" in settings (revokes all sessions for user).

14Sell flow (individual)

5-step modal stack initiated from the centre Sell tab. Drafts persist (autosave every form blur). Resumable from a "Drafts" banner on Home.

  1. sell-type — Balkans vs Import. Big card with stat (active sellers in market). "MOST COMMON" badge on Balkans. Dealer affordance pinned at bottom.
  2. (Conditional) location selectors — country & city, no "All" option.
  3. sell-form — required fields with breadcrumb. AI-paste-IG-link affordance offered.
  4. sell-photos — 4-min, 8-rec photo upload; cover assignable; optional walkaround video (≤ 30 s, ≤ 50 MB); IG import shortcut.
  5. sell-summary — Read-only review with Edit jumps to relevant step; AI-suggested description; phone confirmation.
  6. sell-options — Standard (free) pre-selected; Top Ad (€49 / 7 d) with sample card preview & bullet benefits.
  7. sell-pub — Confetti + summary card + View / Boost CTAs.
Payments: Top Ad checkout uses Stripe Checkout (cards) + bank transfer fallback (manual approval). On webhook checkout.session.completed, listing gets premium=true, premiumUntil set, push notification "Your ad is now Top Ad".

Validation

  • Mileage 0–1 000 000; year 1950–current+1.
  • Price: warn if > 2× or < 0.5× median for that make/model/year.
  • At least 4 photos required to publish.
  • VIN optional but, if provided, validated against 17-char ISO 3779 + checksum.

15Dealer · social auto-import ⚡

The product's moat. Goal: a dealer connects Instagram once, then their next post becomes a draft listing within 60s.

  1. social-connect — header card explains the value. Provider list with status pill (Synced, Re-auth needed, Connect). Multi-account support — "+ Add another business account".
  2. perms — OAuth consent screen styled in-app for trust. List of scopes requested (read media, receive webhooks, no DMs, no follower data). Continue → routes to provider OAuth (Meta system browser).
  3. importing — live progress card (X of Y), activity feed of AI events. Note that user can leave; sync continues in background.
  4. imported — status-filterable list: Ready (✓), Needs review (⚠), Duplicate (=), Skipped. Bulk-publish ready batch via footer CTA.
  5. ai-review — single post review with source preview (image + caption), auto-filled fields with confidence %, manual override, suggestions for missing fields ("€38k — based on 12 similar listings"). Approve → publish.
  6. dealer-dash — stat cards (active, views/week, chats, response time), sync status, 14-day views chart, top listings.

Sync architecture

// On connect
1. OAuth exchange → store access + refresh tokens (encrypted)
2. Subscribe to Meta webhook for /media, /comments
3. Schedule initial backfill: fetch last 90 days of posts
4. Enqueue extract job per post

// Per-post extract pipeline (BullMQ "import" queue)
post.fetched → media downloaded to R2
            → vision OCR (mileage from photo, plate masking)
            → caption + first-image into gpt-4o-mini:
                "Extract {make, model, year, trim, body, fuel,
                 transmission, price, mileage, location} as JSON"
            → per-field confidence
            → dedupe (VIN | (make+model+trim+year+within 5% price))
            → status: READY (≥ 0.85 avg) | REVIEW (0.6-0.85) | SKIPPED (no car detected) | DUPLICATE

// Updates
webhook(media.deleted) → mark linked Listing as SOLD (if dealer opted-in)
webhook(media.updated) → re-extract, diff against current Listing, surface in REVIEW

Failure modes & UX

  • Token expired → set SocialAccount.status = REAUTH_REQUIRED, push notification "Reconnect Instagram to keep listings syncing", red dot on Connect card.
  • Rate limit (IG/FB) → exponential backoff in BullMQ; expose next retry to dealer UI ("Resumes in 4m").
  • Ambiguous post → REVIEW with a "no car detected" override option; one click marks SKIPPED + trains the per-account ignore filter.
  • Dealer opts out of auto-sold → media deletion only nudges, doesn't change status.
  • Manual edit after publish diverges from source — show a "Source updated" badge instead of overwriting.

Spam & abuse

  • First message between strangers passes through a content classifier. If flagged (off-platform contact request, abuse) → hidden for recipient with a "Suspicious message blocked" notice + Review link.
  • Phone numbers, full URLs and IBANs in messages are masked unless both parties verified.
  • "Report & block" in conversation menu → opens reason picker.
  • Auto-reply for sellers: configurable away-message after X minutes; honour per-locale opening hours.

25Localization

  • Locales at launch: sq (Albanian), mk (Macedonian), sr (Serbian – Kosovo), en.
  • Number & currency formatting via Intl.NumberFormat; price always EUR but locale-formatted.
  • Use ICU MessageFormat for plurals (especially mk & sr cases).
  • Make/model names stay in Latin; cities translated.
  • Date relative formatting in chat with Intl.RelativeTimeFormat.
  • Translation files in i18n/{locale}.json; CI fails on missing keys.

26Accessibility

  • Minimum tap target 44 × 44 pt (already designed for this).
  • Body text supports system Dynamic Type / font scaling up to 130% without clipping.
  • VoiceOver / TalkBack labels on every interactive element; status pills announce role + state.
  • Colour contrast: body text ≥ 7:1 on bg; gold is for fills + iconography only — never gold-on-white body text.
  • Reduced motion preference disables hero animations, page transitions and the auto-scrolling carousel.
  • RTL not required at launch; design respects logical inset / margin properties to make it possible.

27Performance budgets

  • Cold start ≤ 1.6s on a 2020 mid-range Android. Hermes + JSC fallback.
  • Home interactive ≤ 800ms after warm start.
  • Listing detail JS bundle ≤ 60KB gzipped above-the-fold.
  • Image first-byte ≤ 200ms (Cloudflare hot cache); largest contentful paint ≤ 1.2s.
  • Realtime: chat message round-trip p95 ≤ 600ms in-region.
  • API p95 ≤ 250ms (excluding image generation).

Offline behaviour

  • Listings cached for 24h in MMKV.
  • Favourites + recently viewed work offline; mutations queued and replayed.
  • Chat shows last-known messages with a "Reconnecting…" pill; outgoing messages enter a "pending" state.
